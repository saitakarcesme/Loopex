# Synthetic performance protocol 3

This harness submits no prompts and runs no models. Provider catalog discovery still runs normally. It requires the current offline seed with exactly 1,000 tasks, 10,000 messages, 5,000 completed turns, and a 1,000-message heavy conversation containing long TypeScript code, a wide table, Turkish text and emoji. The database counts are checked read-only before launch and after confirmed main-process exit using the project's Electron runtime in `ELECTRON_RUN_AS_NODE=1` mode and its matching `better-sqlite3` dependency. The helper passes `readonly: true, fileMustExist: true`, uses the canonical database path, and preserves SQLite's normal WAL handling. It does not use `immutable`, ignore a WAL, checkpoint the database, or change permissions. Actual Electron/Node/ABI versions, module/executable/database paths and the connection's readonly flag are recorded for each count check.

Run three sequential measurements against the same frozen package, using a fresh seed directory for each. Keep the app foregrounded, use the same display/window arrangement, and avoid concurrent model, build or benchmark work. The harness does not seed or overwrite an existing directory.

```sh
TSX_TSCONFIG_PATH=tsconfig.v2.json ELECTRON_RUN_AS_NODE=1 ./node_modules/.bin/electron --import tsx v2/tests/e2e/seed-performance.ts --user-data /tmp/akorith-b03-perf-1
node v2/tests/e2e/performance-v3.cjs --run --package-id B03 --app "/path/Akorith Next.app" --user-data /tmp/akorith-b03-perf-1 --output /tmp/akorith-b03-perf-report-1
```

Repeat with new `-2` and `-3` directories. `performance.cjs` forwards to this named version. The default soak is 120,000 ms. A different `--soak-ms` is recorded as nonstandard and should not enter the three-run comparison.

Every run follows the same path:

1. Measure LaunchServices invocation to a visible composer. Hashing the package before launch warms the filesystem cache; this is not a cold-start measurement.
2. Wait up to 120 seconds for Codex, Claude, OpenCode and Ollama to leave `Checking`, with `providerRefreshPending=false` on two consecutive polls. An unavailable or unauthenticated provider is settled and recorded; it is not reported as authenticated. Discovery wait and transitions are separate from UI interaction timing.
3. Warm up targets 0 and 3 through the real Search tasks dialog. Then measure target indices `0,1,2,3,0,1,2,3,0`, where the seed indices represent the heavy conversation, task 0001, task 0500 and task 0999.
4. Each target is revealed by opening Search tasks and entering its exact title. That reveal duration is separate. Switch duration starts at the actual capture-phase click on the matching search result, before React handles it. It ends on the second animation frame after the selected sidebar title and all mounted message task IDs match. Playwright lookup, actionability and click dispatch overhead are excluded from switch timing and recorded separately.
5. Type the same Turkish/emoji synthetic draft without submitting it. Record input-event-to-two-animation-frames latency, clear the draft, scroll the heavy transcript, and alternate top/bottom scrolls with actual memory samples during the two-minute soak. These timings do not measure keyboard hardware, wheel/trackpad latency or model generation.
6. Record frame intervals, long tasks where available, DOM counts, visibility changes, errors and a final screenshot. Assert at most 31 sidebar task rows, 100 mounted messages and exactly one transcript region. Hidden-page measurements fail. Missing renderer working-set metrics remain `null`, never substituted with zero.
7. Save measurements before cleanup, send SIGTERM only to the exact owned main PID, and wait for `ESRCH`. EPERM and other probe failures remain unknown. After 30 seconds, a same-identity owned process may receive SIGKILL with a further five-second wait. Forced cleanup is recorded as a failed run even if the PID disappears. Save the final cleanup result and post-exit fixture counts to `performance.json`.

SIGTERM cleanup is **not normal application Quit testing** and main-PID disappearance does not independently certify every descendant's quiescence. Root's separate packaged lifecycle journey provides that evidence. Startup/interaction failures retain their report and trigger the same owned cleanup. Preflight argument/fixture validation fails before launching the app and writes `failureStage: "preflight"`, `completed: false`, `successful: false` and `cleanup.notLaunched: true` to the report. A report destination is established before preflight reads; without `--output` it is a new system-temporary directory outside the unvalidated user-data path. An unwritable report destination is necessarily a command failure rather than a saved report.

The original B03 preflight attempt failed in the system SQLite CLI with `unable to open database file (14)` before app launch. Its root cause has not been established; later Python/canonical-path CLI reads succeeded. The helper now uses the matching application dependency runtime instead of that CLI. `node --test v2/tests/e2e/performance-preflight.test.cjs` verifies fresh closed-WAL and active-WAL synthetic databases, missing-file noncreation, and a durable no-launch preflight failure. These small tests use Electron only in Node mode and do not execute the GUI or any model. All three B03 measurements must restart with the updated harness hash; the failed preflight is not a completed performance run.

The report records protocol version, protocol and harness hashes, actual `app.asar` hash, package ID, sample path, raw samples, errors and cleanup. All three comparable runs must have matching protocol/harness/package hashes, standard soak, successful cleanup and no unexpected count changes. B01 used a different sidebar and timing protocol; B01 and protocol-3 values cannot be compared directly as a performance improvement claim.
